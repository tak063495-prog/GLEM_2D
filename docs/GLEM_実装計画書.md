## 1. 目的と前提

### 1.1 目的

本計画は、GLEM の実装をマイルストーン単位で管理するための計画である。作業分解（WBS）、工数見積、各マイルストーンの完了基準（DoD）、リスク管理を含む。

### 1.2 前提条件

| 項目 | 前提 |
|---|---|
| 開発体制 | **開発者2名**（A: コアエンジン中心 / B: UI・IO 中心）＋レビュー担当1名（兼任可）。開発者1名のみの場合は §3.4 の代替スケジュールを適用する |
| 総工期 | **8週間**（稼働日ベース、週5日） |
| 技術スタック | C# / .NET 8 + WPF（詳細設計書 §2.3 で確定済み） |
| 作業環境 | リポジトリ・CI（GitHub Actions）・Issue 管理が利用可能であること |
| 要件の凍結 | M1 開始時点で機能仕様書 v1.0 の要求事項を凍結する。以降の変更は §7 の変更管理フローで承認する |

## 7. 変更管理方針

1. **要件凍結**: M1 開始時点で機能仕様書 v1.0 の要求事項を凍結する
2. **変更申請**: 凍結後の要求追加・修正は、影響範囲（工数・文書・テスト）を記した変更提案として Issue に起票する
3. **承認**: レビュアーが §5 リスクレジスタと照合のうえ承認/却下する。承認された変更は該当文書（機能仕様書→基本設計書→詳細設計書→テスト計画書の順に）を改訂し、改訂履歴を更新する
4. **軽微な修正**: 文言・既定値の変更で工数影響が1人日以内の場合は、レビュアーの口頭承認＋文書更新で対応する
